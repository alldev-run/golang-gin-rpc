# 框架插件化重构:pkg 大杂烩 → 核心内核 + 独立插件模块

## Context

当前 41 个 pkg/* 包全部挤在一个 Go module 里,启动顺序硬编码在 `internal/bootstrap/framework_entry.go` 的 `StartFramework`(`if options.InitXxx` 串),依赖通过 `dependencies map[string]interface{}` 手工传递。用户要将功能包拆成可独立维护的模块(之后各自搬去独立仓库),框架以插件方式按需加载:**未 import 的不参与链接,未启用的不参与运行**。

已确认的决策:
- 加载机制:**编译期注册 + 配置驱动**(Go 生态标准模式,非 .so 动态加载)
- 范围:**全部拆分,一步到位**
- 模块路径:挂当前仓库下 `github.com/alldev-run/golang-gin-rpc/plugins/<name>`,搬仓库时只需改 go.mod 模块名

**核心/插件判定原则**:kernel + 几乎所有应用都要的(config/logger/errors/status_code/response/panicx/requestid/cors/utils/version)留核心;其余全是插件。插件模块依赖核心模块(kernel/config/logger)与其他插件模块,核心**零插件依赖**。

## 插件机制设计(pkg/kernel,~300 行 + 测试)

```go
type Plugin interface {
    Name() string
    Depends() []string              // 运行时启动顺序依赖(按 Name)
    Configure(ctx *Context) error   // 解析自己的配置段;未启用则返回 ErrDisabled
    Start(ctx context.Context) error
    Stop(ctx context.Context) error
}

type Context struct { /* Config() *config.Loader、Logger()、SetService/GetService(替代 dependencies map) */ }

func Register(p Plugin)                    // 插件包 init() 或应用侧显式调用
func NewLoader(cfg, opts...) *Loader
func (l *Loader) Build() (*App, error)     // 过滤已注册+已启用 → Depends 拓扑排序 → 环检测 → App
func (a *App) Start(ctx) / Stop(ctx)       // 顺序启动(失败回滚已启动)、逆序停止
```

启用规则(对应"不用的就不加载"):
- **链接期**:应用只 import 需要的插件包,未 import 的根本不进二进制
- **运行期**:配置 `plugins.<name>.enabled: false` 可关闭已注册插件;无 `enabled` 字段默认启用

## 实施步骤

1. **pkg/kernel**:接口/注册表/拓扑排序/环检测/服务定位器 + 单测(`go test ./pkg/kernel/`)
2. **解耦 config→upload**:`pkg/config/config.go:12,59-65` 移除 `upload.Config` 内嵌,改用新增的 `Loader.UnmarshalSection(name, out)`(raw yaml 段访问,插件自带配置结构体);`UploadConfig` 定义移入 plugins/upload
3. **目录迁移 + 模块化**(机械步骤,git mv + 脚本改 import):
   - 每个 plugins/<name>/ 写 go.mod(module 路径、require 核心与所依赖插件)
   - 全仓 `sed` 重写 import:`.../pkg/actor` → `.../plugins/actor` 等(含子包 db/mysql、middleware/gin);gofmt 收尾
   - `pkg/router`、`pkg/middleware/gin|nethttp`、`pkg/httplog` 并入 plugins/gateway(消除 gateway↔middleware 模块环)
   - `pkg/rpc/examples` → `examples/rpc-lib/`;`pkg/integration`、`pkg/db/integration` → `internal/testutil/`
   - go.work 更新;各模块 `go mod tidy`
4. **插件适配器**:每个插件包新增 `plugin.go` 实现 kernel.Plugin(逻辑从 internal/bootstrap 对应 `Initialize*` 方法迁移:db/cache/discovery/tracing/auth/metrics/health/errors/upload/rpc/gateway/websocket);`internal/bootstrap/plugins.go` 统一 blank-import 全部内置插件(应用裁剪时只改这一个文件)
5. **改造 Bootstrap**:`StartFramework` 改为 kernel.Load+Start(拓扑序替代硬编码 if 链);`dependencies` map 由 kernel 服务定位器承接;`ManagedService`/`ServiceFactory`(api-gateway/rpc/websocket)保留,从 kernel 取依赖;`pkg/bootstrap` 门面签名不变(api/http-gateway 无需改动业务代码);config.yaml 的 `framework.init_*` 迁移为 `plugins.*.enabled`,`framework.services` 保留
6. **db 上帝工厂改造**:pkg/db 工厂的 mysql/postgres/clickhouse/mongodb/es 静态 import 改为驱动注册表(driver 在各自子包 init 时注册),不 import 的驱动不链接
7. **收尾**:examples 重复 main 修复(按子目录拆分)+ import 更新;Makefile/start.sh 增加 plugins 目录的 build/test 循环;config.yaml 默认配置更新

## 验证

- `go build ./...`(根)+ 循环 `for d in plugins/*/; do (cd $d && go build ./... && go test ./...)`;go.work 下逐模块验证
- `go vet` 全部模块;`go test -race ./pkg/kernel/... ./internal/... ./plugins/actor/... ./plugins/gateway/...` 抽查
- 端到端:`make build && ./bin/alldev-gin-rpc` 起服务,验证 /health 与 api-gateway 路由;把 config.yaml 中某插件 `enabled: false` 重启,确认日志中该插件未加载、其余正常
- 裁剪演练:临时注释 internal/bootstrap/plugins.go 中一行 import,确认对应插件从注册表消失且编译通过(验证"不用不加载")

## 风险与边界

- 大规模 import 重写是唯一高危机械步骤:在新分支操作,sed 后全量编译兜底
- 不改各插件内部业务逻辑,只动目录/import/生命周期接入,失败测试(gateway/websocket/db 的预置问题)不在本次范围
- 搬独立仓库时:复制 plugins/<name> → 改 go.mod 模块名 → 依赖方改 import 前缀,本次架构已保证无其他动作
